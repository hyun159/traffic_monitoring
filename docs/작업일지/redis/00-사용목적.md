

## Redis 사용 목적
```
데이터 처리가 빠른 인메모리 방식이다.
주로 빠르고 실시간 처리를 위해 사용된다.
- 세션 저장소
- 메시지 큐
- 실시간 순위표
- 분산 락
- 호출 제한
```


## Redis 싱글 스레드
```
GET, SET, SADD 명령어 실행, 네트워크 처리 등 모든 작업은 메인 스레드가 동작함.

Redis 6.0 버전 부터 네트워크 패킷 읽기,쓰기는 I/O스레드가 멀티스레드로 동작.
실시간 쌓이는 GET, SET 패킷을 I/O 스레드가 병렬로 읽어와 메모리에 정렬.
메인 스레드가 GET, SET을 하나씩 처리함.
```


## 교통정보 프로젝트에 레디스가  사용된 이유
```
Frontend의 app.js는 5분마다 백엔드에게 낙동강다리의 실시간 교통정보 API를 요청한다.
백엔드는 app.js의 요청을 받고 ITS에게 5분마다 요청한다.

ITS의 응답한 데이터는 백엔드 변수에 저장되고 5분마다 새로 덮어씌워진다.
만약 APP 서버 또는 APP 컨테이너가 다운되면 변수 데이터를 보존해야하며
새 컨테이너를 실행하여 데이터를 유지할 수 있어야한다.
따라서 app을 stateless 상태로 운영하고 외부 캐싱을 사용한다.
```
