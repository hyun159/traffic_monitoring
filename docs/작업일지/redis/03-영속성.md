# 인메모리 영속성 관리


## 1. 영속성 방식
### RDB
```
특정 시간마다 전체 스냅샷을 디스크 기록

장점
최종 데이터 상태만 바이너리 형태로 압축하여 용량이 작다.
파일 내용을 메모리에 그대로 복사하여 빠르게 복원 가능.
스냅샷을 디스크에 저장할 때 자식프로세스가 사용되어 비동기 형식으로 성능 영향이 적다.

단점
5분 15분 단위이므로 데이터 유실 발생 위험.
CoW 방식으로 디스크에 기록될 때 메모리 사용률이 증가하여 OOM 발생 가능성이 있다.

빠른 복원을 지원, 데이터 손실 위험
```

### AOF
```
모든 쓰기 명령을 로그 형태로 기록

장점
명령어 실행 때마다 파일에 기록하여 1초 이내 데이터만 유실
redis-check-aof 툴을 사용하여 마지막 파손된 명령어만 잘라내어 복구가능

단점
재시작 시 AOF에 기록된 모든 명령어를 순차적으로 실행하여 복원 시간이 오래걸림.
주기적으로 디스크 동기화 fsync를 수행하여 쓰기 작업이 많은 환경에서 성능 저하 위험

안정성에 초점이 맞춰져있고 상대적으로 느림

```

---

## 2. AOF 디스크 동기화

### appendfsync
```
AOF에 기록된 데이터를 언제 디스크에 동기화할지 설정한다.
```
```bash
appendfsync everysec

# always : 쓰기 명령마다 즉시 동기화
# everysec : 약 1초마다 동기화
# no : 디스크 동기화를 OS에 맡김
```

```yaml
 # Docker에서는 네임드 마운트를 사용한다.

 volumes:
      - redis_data:/data
```
